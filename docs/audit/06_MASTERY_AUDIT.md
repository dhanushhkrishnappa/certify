## 1. Executive Summary

> *"Chapter assessments provide evidence of understanding... Deterministic backend rules decide certification outcomes... Mastery progression must be traceable, mathematically grounded, and auditable."*

**Key Findings:**
1. **Mathematical Implementation is Sound:** The core Bayesian Knowledge Tracing implementation in `backend/src/modules/mastery/bkt.ts` correctly executes standard BKT update formulations (clamped priors, slip/guess conditionals, transition probabilities).
2. **Deterministic & Persisted:** Updates correctly mutate `ConceptMastery` rows in SQLite and write immutable `MasteryEvidence` audit records.
3. **CRITICAL FLAW — Observation Input is Compromised (P0):** While the mathematical function `BayesianKnowledgeTracer.update()` is valid, the observation signal (`isDemonstrated: boolean`) fed into this function is generated by crude substring keyword checks (`userLower.includes("pointer")`, `answerLower.length > 20`). A learner can reach 99% mastery across all concepts simply by typing a single sentence containing 10 technical keywords.

## 2. Mathematical Formulation Audit (`bkt.ts`)

The BKT engine operates on three standard parameters defined in `backend/src/modules/mastery/bkt.ts:7-11`:
- $P(T) = 0.20$ (Probability of learning transition per step)
- $P(G) = 0.10$ (Probability of a lucky guess / false positive)
- $P(S) = 0.05$ (Probability of a slip / careless mistake)
- Initial Prior: $P(L_0) = 0.15$ (Set upon course enrollment in `courses.controller.ts:114`)

### Mathematical Verification:
1. **Observation Update:**
   - **For correct demonstration ($Obs = 1$):**
     $$P(L \mid Obs=1) = \frac{P(L) \cdot (1 - P(S))}{P(L) \cdot (1 - P(S)) + (1 - P(L)) \cdot P(G)}$$
     *Code verification (`bkt.ts:28-31`):*
     ```typescript
     const num = clampedPrior * (1 - pS);
     const denom = num + (1 - clampedPrior) * pG;
     pPosterior = num / denom;
     ```
     **Status: Verified Correct.**
   - **For incorrect demonstration ($Obs = 0$):**
     $$P(L \mid Obs=0) = \frac{P(L) \cdot P(S)}{P(L) \cdot P(S) + (1 - P(L)) \cdot (1 - P(G))}$$
     *Code verification (`bkt.ts:33-37`):*
     ```typescript
     const num = clampedPrior * pS;
     const denom = num + (1 - clampedPrior) * (1 - pG);
     pPosterior = num / denom;
     ```
     **Status: Verified Correct.**
2. **Transition Update:**
   $$P(L_{t+1}) = P(L \mid Obs) + (1 - P(L \mid Obs)) \cdot P(T)$$
   *Code verification (`bkt.ts:40`):*
   ```typescript
   const pNext = pPosterior + (1 - pPosterior) * pT;
   ```
   **Status: Verified Correct.**
3. **Clamping & Bounds:**
   - Prior is clamped: `Math.min(Math.max(pCurrent, 0.01), 0.99)`.
   - Posterior is clamped and formatted: `Number(Math.min(Math.max(pNext, 0.01), 0.99).toFixed(4))`.
   - Prevents division-by-zero or mathematical probability overflow.

## 5. Security & Gaming Vulnerability Analysis

### Scenario: Zero-Knowledge Mastery Bypass
Because the observation logic does not check semantic validity, an uneducated actor or bot can send the following string in the chat or assessment:

```
"pointer reference lazy on-demand closure encapsulate nonlocal immutable hash o(1) stream with cleanup"
```

1. **In Learning Studio:**
   - Immediately triggers lines 226-265 in `sessions.controller.ts`.
   - $P(L)$ jumps from $0.15 \rightarrow 0.7011$ on turn 1.
   - Repeating the string once more pushes $P(L)$ to $0.9824$.
   - The concept state immediately updates to `MASTERED`.
   - The chapter gate unlocks and allows advancing to the next chapter.
2. **In Assessment Submission:**
   - Any answer containing 21 characters with one keyword demonstrates all rubric criteria.
   - Yields a score of `1.0` (100%) and sets all chapter concepts to `MASTERED`.

### Client Manipulation Risk:
Can the frontend directly submit arbitrary `pMastery` values?
- **Finding:** No endpoint accepts a raw `pMastery` float from `req.body`. The value is always calculated server-side in `BayesianKnowledgeTracer.update()`.
- **However:** Because the server-side inputs are trivially spoofable with keywords, the defense-in-depth provided by server-side execution is completely undermined.

## 6. Audit Trail & Evidence Integrity

In `schema.prisma:176-187`, the `MasteryEvidence` table records:
```prisma
model MasteryEvidence {
  id                  String           @id @default(uuid())
  conceptMasteryId    String
  rubricCriterionId   String?
  evidenceType        String           // DIALOGUE_PROBE, CHAPTER_ASSESSMENT, PRACTICAL_TASK, VIVA
  isDemonstrated      Boolean
  evidenceQuote       String?
  evaluatorReasoning  String?
  createdAt           DateTime         @default(now())
}
```

### Evidence Recording Audit:
- **Recorded correctly:** When a keyword match occurs in `sessions.controller.ts:268` or `assessment.controller.ts:150`, a `MasteryEvidence` record is created with `evidenceQuote` containing the student's text.
- **Auditing Gap:** The `evaluatorReasoning` is a static boilerplate string (`"Learner accurately articulated core conceptual mechanics in dialogue."`), providing no genuine pedagogical rationale or rubric traceability.

## 7. Required Mastery Remediation Tasks

1. **[P0] Decouple BKT from Substring Matching:** Remove the hardcoded keyword lists in `sessions.controller.ts` and `assessment.controller.ts`.
2. **[P0] Integrate Structured LLM Observation Evaluator:** Use structured JSON outputs from Claude/Gemini to evaluate learner answers against specific `RubricCriterion` statements, passing a verified boolean `isDemonstrated` to BKT.
3. **[P1] Connect Diagnostic Test to BKT Priors:** Replace the hardcoded $P(L_0) = 0.15$ with calibrated priors determined by an authentic backend-graded diagnostic assessment.
4. **[P1] Connect Remediation Drills to BKT Updates:** Implement a backend endpoint `POST /api/v1/mastery/remediate` that records successful remediation drill completion and transitions concepts from `NEEDS_REMEDIATION` to `LEARNING`/`MASTERED`.
5. **[P2] Dynamic BKT Parameter Tuning:** Allow `pT`, `pG`, and `pS` to vary by concept difficulty tier (Foundational concepts: higher $pT$; Advanced concepts: lower $pG$, higher $pS$).
