## A. Current Product State

CERTIFY is currently a **partially functional prototype with simulated core features**. 

The UI presents an aesthetically sophisticated interface with 18 distinct views across authenticated, public, and administrative modes. The foundational web plumbing (user registration, login with JWT, course listing, enrollment, and baseline SQLite persistence via Prisma) is functional.

However, the core promises of the platform—**AI-driven adaptive tutoring, multi-modal evidence collection, practical sandbox execution, and cryptographically verified certification**—are largely simulated using keyword heuristics, hardcoded numerical constants, and client-side fallbacks. The product cannot be released or marketed as an AI learning and certification platform in its current state.

---

## B. What Actually Works (Verified Features Only)

1. **User Authentication:** Registration (`POST /api/v1/auth/register`), Login (`POST /api/v1/auth/login`), password hashing via `bcrypt`, 7-day JWT generation, and profile loading (`GET /api/v1/auth/me`).
2. **Course Catalog & Seed Data:** Seeded database (`dev.db`) contains the flagship course *Python Fundamentals* with 8 modules, 8 chapters, 8 concepts, 8 rubrics, 8 rubric criteria, and 8 questions. Browsable via `GET /api/v1/courses` and `GET /api/v1/courses/:slug`.
3. **Course Enrollment & BKT Initialization:** Students can enroll (`POST /api/v1/courses/:slug/enroll`), creating an active `Enrollment`, a `LearningSession`, and 8 `ConceptMastery` rows initialized to $P(L_0) = 0.1500$.
4. **Session Context Hydration:** `GET /api/v1/courses/:slug/session` retrieves enrollment state, current chapter, concept masteries, and conversation history.
5. **Deterministic BKT Math Engine:** `BayesianKnowledgeTracer.update()` mathematically implements sound BKT updates with priors, slips, guesses, and transitions, verified by passing unit tests in `bkt.test.ts`.
6. **Frontend Routing & View Transitions:** React view switcher seamlessly navigates between Landing, Catalog, Details, Studio, Assessment, Remediation, Viva, Dashboard, Credentials, and Admin screens.
7. **Production Compilations:** Both `backend` (`tsc`) and `frontend` (`vite build`) compile with zero build errors.

---

## C. What Does Not Work (Verified Failures)

1. **AI Tutor is Completely Mocked:** There is no LLM provider SDK, API key, or prompt pipeline. All tutor replies are generated by 11 substring keyword checks and hardcoded string arrays streamed via synthetic `setTimeout(80ms)` timers.
2. **Certification Evidence is Fabricated:** 4 of 5 components in `issueCertificate` (`practicalScore = 0.92`, `vivaScore = 0.88`, `consistency = 0.86`, `interactionDepth = 0.82`) are hardcoded constants. Certificates are issued on fictitious data.
3. **Public Verification Catch-All False Positive:** Querying any invalid, non-existent, or revoked credential ID at `/verify/:id` triggers a frontend `.catch()` block that renders a verified badge for "Sophia Chen" in "Distributed Systems" (94.8%).
4. **Code Execution Sandbox Does Not Exist:** Frontend calls `POST /api/v1/execute`, which 404s, falling back to a client-side string `0 errors detected`. In `FinalAssessmentView.tsx`, clicking "Run Tests" unconditionally marks all tests as "passed".
5. **Horizontal Privilege Escalation (IDOR):** Neither `streamMessage`, `advanceChapter`, `submitChapterAssessment`, nor `conductVivaTurn` verifies that `req.user.id` owns the session or enrollment being modified.
6. **Chapter Assessment Submission Bypass:** `ChapterAssessmentView.tsx` runs hardcoded TypeScript Raft/Quorum code, never calls `api.submitChapterAssessment`, and simply navigates to the next view on click.
7. **Diagnostic & Remediation are Transient:** Both `DiagnosticView.tsx` and `RemediationStudioView.tsx` execute purely in React state, never persisting answers, attempts, or calibrated mastery to the backend.

## E. Architecture Problems

1. **Missing Service Layer:** All business logic, BKT updates, evidence creation, and database queries are tightly coupled inside Express controller handlers.
2. **Missing Database Transactions:** Multi-entity operations (e.g. submitting an assessment, which touches 5 tables) are executed sequentially without `prisma.$transaction`.
3. **Database Engine Divergence:** Architecture documents specify PostgreSQL 16+ with `pgvector`; actual code runs on local SQLite (`file:./dev.db`) with zero vector or embedding capabilities.
4. **Transient Oral Viva:** Viva oral defense is conducted via transient request-response turns without database persistence or audio transcription.

## H. Security Readiness: 30% (High Vulnerability)

- **Authentication:** Functional (JWT + bcrypt).
- **Authorization:** Severely flawed. Missing resource ownership checks on 4 major endpoints (IDOR/BOLA).
- **Input Validation:** Absent. No schema validator (`zod`) active.
- **Rate Limiting:** Absent. No protection against credential stuffing or API flooding.
- **Cryptographic Grounding:** Flawed. HMAC-SHA256 with shared server secret masquerading as Ed25519 public key infrastructure.
